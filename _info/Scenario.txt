Scenario (Hybrid Facade) — архитектурное описание
    1. Фасад уровня приложения, определяющий алгоритм выполнения текущего запуска приложения.
        является единственной точкой входа в бизнес-процесс приложения;
        управляет полным жизненным циклом выполнения;
        скрывает внутреннюю сложность подсистем:
        загрузку данных,
        выбор источников,
        работу браузера,
        сохранение результатов,
        обработку ошибок;
        не содержит знаний о конкретных сайтах, селекторах или Playwright.
        Scenario реализует паттерн Facade и концептуально соответствует Use Case / Application Service.
    2. Располагается между App и низкоуровневыми слоями:
            index.ts
                ↓
            App (Composition Root)
                ↓
            Scenario (Facade / Use Case)
                ↓
            Source (Strategy)
                ↓
            Browser (Adapter)
                ↓
            Storage
        знает абстракции нижних слоёв;
        не зависит от их конкретных реализаций;
        не передаёт управление внешнему коду после старта.
    3. Архитектурная модель Hybrid Scenario
        Facade — снаружи один простой способ запуска;
        Template Method — внутри фиксированный алгоритм;
        Явные фазы — логическая прозрачность и расширяемость.
        Внешний контракт
            Scenario предоставляет один публичный метод запуска, скрывающий весь процесс выполнения.
        Внутреннее устройство
            Внутри Scenario выполнение разбито на логические этапы (фазы),
            каждая из которых решает строго одну задачу.
    4. Жизненный цикл Scenario выполняется строго последовательно:
        Схемы:
            Scenario
                ├─ load() → получает массив Task (например CollectProductPhotosTask)
                ├─ prepare() → инициализация окружения
                ├─ process(tasks)
                │    └─ перебирает задачи
                │         └─ для каждой задачи:
                │              1. выбирает Source по типу задачи
                │              2. вызывает Source через Browser
                │              3. получает результат
                │              4. сохраняет через Storage
                ├─ handleError(error) → централизованная обработка ошибок
                └─ finalize() → освобождение ресурсов, закрытие Browser

                Описание:
                    Scenario управляет процессом целиком.
                    Scenario не знает деталей сайта и Playwright, только абстракции.
                    Все операции с внешними системами идут через нижележащие слои.

            Scenario → Source
                ├─ Source получает конкретный Task
                ├─ Source знает, как открыть страницу товара и достать данные
                ├─ Source ничего не знает о Scenario и Browser напрямую

                Описание:
                    Source реализует Strategy для конкретного сайта.
                    Source возвращает результаты (например, URL фото) обратно Scenario.
                    Scenario решает, что делать с результатом (сохранить через Storage, логировать и т.д.).

            Scenario → Browser (IBrowser)
                ├─ runInContext(fn, options)
                │     └─ предоставляет контекст браузера (Context)
                │          └─ Source выполняет действия на странице
                ├─ init() / close() → управление жизненным циклом браузера

                Описание:
                    Scenario не вызывает Playwright напрямую.
                    Browser адаптирует Playwright под единый интерфейс для Scenario.
                    Жизненный цикл браузера (Browser → Context → Page) полностью скрыт.

            Scenario → Storage
                ├─ save(result) → сохраняет файлы / данные
                ├─ определяет структуру каталогов и имена файлов
                ├─ абстрактно: может быть FileStorage / S3 / FTP

                Описание:
                    Scenario не знает технических деталей сохранения.
                    Storage полностью изолирован от Browser и Source.
                    Scenario отвечает только за что и когда сохранять.


        4.1 Load — загрузка входных данных
            Назначение:
                загрузка Job и связанных структур данных;
                подготовка списка задач для выполнения.
            Характеристики:
                работает только с Data Layer;
                не содержит логики выполнения;
                не взаимодействует с Browser, Source или Storage.
        4.2 Prepare — подготовка окружения
            Назначение:
                инициализация технического окружения выполнения;
                подготовка логирования;
                предварительные проверки (не бизнес-логика).
            Характеристики:
                не выполняет задач;
                не загружает страницы;
                может подготавливать общие ресурсы.
        4.3 Process Tasks — основной цикл выполнения
            Назначение:
                перебор задач из Job;
                выбор соответствующего Source для каждой задачи;
                делегирование извлечения данных;
                управление потоком выполнения.
            Характеристики:
                Scenario не знает, как именно Source извлекает данные;
                Scenario не управляет страницами или селекторами;
                взаимодействие с браузером происходит только через абстракцию Browser;
                каждая задача обрабатывается изолированно.
        4.4 Handle Errors — обработка исключений
            Назначение:
                централизованная обработка ошибок;
                принятие решений:
                повторить,
                пропустить,
                прервать сценарий.
            Характеристики:
                Source и Browser могут выбрасывать исключения;
                только Scenario принимает решение о реакции;
                ошибки логируются на уровне сценария.
        4.5 Finalize — завершение выполнения
            Назначение:
                корректное завершение работы сценария;
                освобождение ресурсов;
                финальное логирование;
                сохранение итогового состояния.
            Характеристики:
                вызывается всегда, независимо от успеха или ошибки;
                не содержит логики выполнения задач.
    5. Ответственность и границы Scenario
        Отвечает за:
            алгоритм выполнения;
            порядок действий;
            связывание абстракций;
            контроль жизненного цикла;
            обработку исключений;
            целостность процесса.
        Не отвечает за:
            селекторы и DOM;
            навигацию по сайту;
            детали Playwright;
            формат хранения данных;
            конкретные сайты.
    6. Расширяемость и замена сценариев
        Архитектура ПРЕДПОЛАГАЕТ:
            неограниченное количество сценариев;
            разные алгоритмы выполнения (batch, single, debug, dry-run);
            замену Scenario без изменения App или index.ts.
        Каждый Scenario:
            изолирован;
            реализует один режим работы приложения;
            использует одни и те же Source / Browser / Storage абстракции.
    7. Ключевые архитектурные инварианты
        Scenario — Facade, независимо от внутренней сложности.
        Внешний код не управляет шагами выполнения.
        Все зависимости направлены вниз.
        Playwright остаётся технической деталью.
        Алгоритм выполнения зафиксирован в одном месте.
