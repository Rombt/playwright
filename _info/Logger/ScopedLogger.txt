ScopedLogger — это контекстный логгер, предназначенный для логирования в рамках одной конкретной задачи (Job / Scenario).
    Обеспечивает:
        автоматическое добавление contextId ко всем лог-записям
        изоляцию параллельных процессов
        единообразное и предсказуемое логирование по всей глубине вызовов
        ScopedLogger не является инфраструктурным логгером и не управляет конфигурацией логирования.
    Архитектурная роль
        ScopedLogger представляет собой immutable-обёртку над корневым (root) логгером.
        Root logger — инфраструктура
        Scoped logger — контекст выполнения
        Связь реализована через композицию, а не наследование.
    Ответственность
        ScopedLogger
            отвечает только за:
                хранение неизменяемого contextId
                формирование ILogEntry с привязкой к контексту
                делегирование записи корневому логгеру
            не выполняет:
                фильтрацию по уровням
                форматирование
                управление transports
                работу с файловой системой или консолью
                хранение бизнес-данных
    Контекст (ContextId)
        Назначение
            contextId — уникальный идентификатор задачи (Job / Scenario).
        Используется для:
            корреляции логов
            фильтрации
            анализа конкретного выполнения
            отладки параллельных процессов
        Свойства
            задаётся при создании ScopedLogger
            является обязательным и неизменяемым
            автоматически добавляется ко всем лог-записям
        Изменение или вложенность контекста запрещены.
        Иммутабельность
            После создания:
                contextId не может быть изменён
                новый контекст не может быть создан из текущего
                Попытка вызвать withContext() приводит к ошибке.
            Это гарантирует:
                отсутствие “перетекания” логов между задачами
                корректную работу при параллельном выполнении
                предсказуемое поведение системы
        Взаимодействие с root logger
            ScopedLogger содержит ссылку на корневой логгер и использует его для записи:
            ScopedLogger → Root Logger → Transports
    Корневой логгер:
        Назначение
            проверяет уровень логирования
            управляет transports
            отвечает за инфраструктурный вывод
        Поток формирования лог-записи
            При вызове любого метода логирования:
            ScopedLogger получает сообщение и метаданные
            Формирует структурированную запись (ILogEntry)
            Добавляет contextId
            Делегирует запись root logger
        Использование в системе
            Создание
                const logger = Logger.getInstance().withContext('job-123');
            Передача вниз по слоям
                Scenario → Source → Browser → Storage
                Все слои используют один и тот же экземпляр ScopedLogger.
            Ограничения
    ScopedLogger:
        не хранит состояние задачи
        не принимает бизнес-решения
        не знает о структуре системы
        не зависит от внешних библиотек
        не управляет жизненным циклом логирования
    Причины отказа от наследования от Logger
        наследование позволило бы модифицировать состояние root logger
        нарушалась бы изоляция контекста
        появлялась бы возможность доступа к transports
        Композиция гарантирует архитектурную чистоту.
