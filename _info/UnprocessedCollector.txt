UnprocessedCollector – Техническое описание
1. Назначение
    UnprocessedCollector — класс уровня Data Layer, предназначенный для работы с необработанными продуктами.
    Основная задача класса — предоставлять Scenario Layer доступ к массиву необработанных продуктов по брендам,
        а также, в более поздних версиях, управлять их статусом (обработанные/неудачные) и предоставлять статистику.
    Класс не занимается прямой обработкой продуктов или взаимодействием с Playwright — это ответственность Scenario Layer и Browser Layer.

2. Расположение в архитектуре
    Data / Job (Repository Storage)
            └── collectors/
                └── UnprocessedCollector.ts
    Scenario Layer вызывает методы Collector для получения продуктов и, на будущее, запуска сценариев обработки.
    Collector работает напрямую с файловой системой и использует глобальный конфиг appConfig для путей.

3. Используемые зависимости
    Глобальный конфиг: appConfig
    Содержит
        пути к папкам брендов, где хранятся необработанные продукты.

Хелперы:
    readProducts(filePath: string): Product[] — чтение продуктов из файла.
    writeProducts(filePath: string, products: Product[]): void — запись продуктов в файл.
    getUnprocessedFilePath(brand: string): string — формирование пути к файлу необработанных продуктов.

4. Основные методы
    4.1 getProducts(brand?: string | string[]): Product[]
        Описание:
            Возвращает массив необработанных продуктов.
        Параметры:
            brand?: string | string[] — бренд или массив брендов. Если не указан, возвращаются продукты всех брендов.
        Возвращает:
            Product[] — массив объектов продуктов.

    4.2 getBrands(): string[]
        Описание:
            Возвращает список брендов, для которых есть необработанные продукты.
        Параметры:
            Нет параметров.
        Возвращает:
            string[] — массив названий брендов.

    4.3 markAsProcessed(products: Product[]): void
        Описание:
            Помечает указанные продукты как обработанные, удаляя их из файлов с необработанными продуктами.
        Параметры:
            products: Product[] — массив продуктов, которые были успешно обработаны.
        Возвращает:
            void.

    4.4 markAsFailed(products: Product[], reason: string): void
        Описание:
            Помечает указанные продукты как неудачные для последующего анализа, добавляя причину ошибки.
        Параметры:
            products: Product[] — массив продуктов, которые не удалось обработать.
            reason: string — причина неудачной обработки.
        Возвращает:
            void.

    4.5 count(brand?: string | string[]): number
        Описание:
            Возвращает количество необработанных продуктов.
        Параметры:
            brand?: string | string[] — бренд или массив брендов. Если не указан, возвращается количество для всех брендов.
        Возвращает:
            number — количество необработанных продуктов.

    4.6 logSummary(): void
        Описание:
            Выводит краткий отчёт по брендам и количеству необработанных продуктов, полезно для логирования и мониторинга.
        Параметры:
            Нет параметров.
        Возвращает:
            void.

5. Возможное будущее расширение
    Фильтрация по произвольным условиям
        Метод filterBy(condition: (product: Product) => boolean, brand?: string | string[]): Product[]
    Batch-run сценариев
        Метод runForBrands(brands: string[], scenario: (products: Product[]) => Promise<void>): Promise<void>
    Интеграция с retry / waitBeforeRetry
        Автоматическая повторная обработка неудачных продуктов
    Экспорт отчётов
        CSV / JSON / Excel

6. Принцип работы
    Collector читает файлы необработанных продуктов по пути из appConfig.
    Scenario Layer вызывает getProducts → получает массив продуктов.
    После успешной обработки вызывается markAsProcessed.
    Если продукт не удалось обработать → markAsFailed.
    Методы count и logSummary позволяют быстро оценить состояние необработанных продуктов.
