UnprocessedCollector
1. Назначение
    UnprocessedCollector — класс Data Layer, предназначенный для работы с необработанными продуктами, полученными в результате выполнения сценариев Playwright.
    Основная задача класса — предоставить Scenario Layer удобный и стабильный доступ к данным:
        массивам необработанных продуктов
        информации о доступных брендах
        агрегированной статистике по количеству продуктов
    Класс не занимается:
        обработкой продуктов
        повторными попытками (retry)
        анализом ошибок
        взаимодействием с Playwright или браузером
2. Архитектурная роль
    Уровень
        Data Layer
    Ответственность
        чтение данных из файловой системы
        агрегация и фильтрация данных
        предоставление статистики
    Вне ответственности
        логика сценариев
        обработка ошибок
        управление потоками выполнения
        любые browser-операции
3. Источник данных
    Формат хранения
        Необработанные продукты хранятся в JSON-файлах в директории results.
    Шаблон имени файла {brand}_unprocessed-products.json
        Пример:
            nike_unprocessed-products.json
            adidas_unprocessed-products.json
    Источник бренда
        Название бренда извлекается исключительно из имени файла
    Структура директорий не используется для определения бренда
4. Нормализация брендов
    В классе зафиксированы следующие правила:
        Регистр не чувствителен
        Все бренды нормализуются к lowercase
        Входной параметр brand
            string → один бренд
            string[] → список брендов
            undefined → все бренды
        Неизвестные бренды
            допустимы
            не вызывают ошибок
            возвращают пустой результат или 0
5. Публичный контракт
    Класс реализует интерфейс IUnprocessedCollector.
6. Возвращаемые данные
    возвращает только сущность продукта согласно interface IProduct
    Контекст ошибки (timeout, retryable, URL и т.п.) игнорируется намеренно и не является частью публичного API класса.
7. Описание методов
    7.1 getProducts(brand?)
        Описание:
            Возвращает массив необработанных продуктов.
        Поведение:
            без параметров → продукты всех брендов
            с string → продукты одного бренда
            с string[] → продукты указанных брендов
        Особенности:
            порядок продуктов не гарантирован
            неизвестный бренд → пустой массив
    7.2 getBrands()
        Описание:
            Возвращает список всех доступных брендов.
        Источник:
            извлекаются из имён файлов {brand}_unprocessed-products.json
        Формат:
            все значения в lowercase
    7.3 countTotal()
        Описание:
            Возвращает общее количество необработанных продуктов по всем брендам.
    7.4 countByBrand()
        Описание:
            Возвращает количество необработанных продуктов, сгруппированное по брендам.
        Формат:
            {
                nike: 12,
                adidas: 4
            }
    7.5 count(brand)
        Описание:
            Возвращает количество необработанных продуктов для указанного бренда или брендов.
        Особенности:
            принимает string | string[]
            всегда возвращает number
            неизвестные бренды → 0
    7.6 getSummary()
        Описание:
            Возвращает сводную статистику по брендам.
        Примечание:
            Метод является семантическим алиасом countByBrand() и предназначен для повышения читаемости кода сценариев.
    7.7 logSummary()
        Описание:
            Выводит краткий отчёт по брендам и количеству необработанных продуктов в стандартный вывод.
        Назначение:
            логирование
            мониторинг
            отладка
8. Зависимости
    Конструктор
        constructor(config: AppConfig)
        Используемые параметры AppConfig
        resultsDir — путь к директории с файлами результатов
    Глобальные конфиги напрямую не используются.
9. Ошибки и отказоустойчивость
    Класс спроектирован как тихий Data Layer:
    ошибки чтения файлов подавляются
    некорректный JSON → пустой результат
    отсутствующая директория → пустой результат
    исключения не пробрасываются наружу
10. Ограничения и сознательные упрощения
    На текущем этапе класс не реализует:
        кеширование
        асинхронное чтение файлов
        сортировку продуктов
        фильтрацию по атрибутам
        расширенную аналитику
        Все эти возможности могут быть добавлены без изменения публичного контракта.
