Приложение для автоматизированного сбора изображений товаров.

    Использует Playwright как движок браузера
    Работает по заданиям (Job) в формате JSON
    Может:
        обрабатывать разные сайты
        разные правила поиска
        разные сценарии сбора


    Формальная модель жизненного цикла
        Для версии 1.0.0 устанавливаю
            Browser инициализируется при старте
            Browser живёт всё приложение
            Context создаётся на сценарий
            Задачи task это набор данных с которыми работает сценарий
            Page создаёт сценарий внутри context
            Context закрывается после завершения сценария
            Browser закрывается при закрытии приложения

        Application start
        └── Browser (1 экземпляр)
            ├── Task #1
            │     └── Context
            │           └── Page(s)
            ├── Task #2
            │     └── Context
            │           └── Page(s)
            └── Task #N
                    └── Context
                        └── Page(s)
        Application shutdown
        └── Browser.close()

        Browser — сервис уровня приложения
        Task это: любой сценарий на конкретной странице
            пример
                парсинг страницы
                логин + действие
                генерация PDF
                проверка состояния сайта
                автоматизация админки
        Context — транзакция / unit of work
            это изолированная среда выполнения == отдельный браузерный профиль
            Контекст дешевле браузера
            const context = await browser.newContext();
        Page — инструмент выполнения



    Архитектура
        Приложение разделено на независимые слои по ответственности - Clean Layers
        Главные архитектурные принципы
            Разделение ответственности
            Зависимость только “вниз”
            Программирование через абстракции
            Данные отдельно от логики
            Playwright — деталь, а не центр системы
        Цель архитектурного решения.
            Каждый слой:
                решает ТОЛЬКО свою задачу
                не знает лишнего
                может быть заменён без переписывания всей системы
        ФАКТИЧЕСКИ используются следующие паттерны
            Clean Layers	Вся система
            Facade Scenario
            Strategy Source
            Adapter Browser
            Repository Storage
        Слои системы (логическая схема)
            [ Data / Job (Repository Storage)]
                    ↓
            [ Scenario (Facade) ]
                    ↓
            [ Source (Strategy) ]
                    ↓
            [ Browser (Adapter) ]
                    ↓
            [ Storage ]
        Подробная роль каждого слоя
            Data Layer (Job, Task, Result)
                Отвечает за:
                    описание:
                    что собирать
                    для каких товаров
                    с каких сайтов
                    хранится в JSON
                    не содержит логики
                    это чистые структуры данных
                Пример сущностей:
                    Job
                    ProductTask
                    CollectResult

            Scenario = Facade = Use Case / Application Service подробное описание в Scenario.txt
                Точка входа в приложение и дирижёр процесса.
                Отвечает за:
                    загрузку Job
                    перебор задач
                    выбор нужного Source
                    управление потоком:
                        открыть
                        получить данные
                        сохранить
                        обработку ошибок
                        логирование
                Не знает:
                    селекторов
                    Playwright
                    структуры сайтов

            Source = Strategy
                Знание КОНКРЕТНОГО сайта.
                Отвечает за:
                    как открыть страницу товара на этом сайте
                    как найти главную картинку
                    какие селекторы использовать
                    как извлечь нужный URL
                Примеры:
                    RozetkaProductSource
                    PromProductSource
                Не знает:
                    про Job
                    про файлы
                    про сценарии
                    про Playwright напрямую

            Browser = Adapter
                Техническая оболочка над Playwright.
                    Простой жизненный цикл
                        один Browser на всё приложение
                        один Context на задачу
                        одна или несколько страниц внутри контекста
                Отвечает за:
                    запуск браузера
                    навигацию
                    поиск элементов
                    скачивание файлов
                Даёт:
                    твой API (а не API Playwright)
                Не знает:
                    зачем это делается
                    что такое товар
                    что такое сценарий


            Storage
                Слой сохранения результатов.
                Отвечает за:
                    сохранение файлов
                    именование
                    структуру каталогов
                    возможную замену:
                        локально
                        S3
                        FTP
                        etc

    Как работает система (поток выполнения)
        Scenario загружает Job
        Для каждого ProductTask:
            выбирает нужный Source
            говорит Source: “открой страницу”
            говорит Source: “дай ссылку на картинку”
        Scenario передаёт URL картинки в Browser для скачивания
        Scenario передаёт файл в Storage для сохранения

    Как это масштабируется
        добавить новый сайт → новый Source
        добавить новый сценарий (например “собирать цены”) → новый Scenario
        заменить Playwright → новый BrowserAdapter
        изменить хранение → новый Storage
